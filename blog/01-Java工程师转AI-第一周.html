一、我为什么没去买课

刚开始其实也想过报一个班，但是想来想去，最终还是放弃了，一个是最近房子装修，经济属实不是很宽裕，另一个嘛就是，机构的能力参差不齐，我个人又不是很喜欢看视频可能，总感觉废话很多，容易走神。

所以最终就想了这个法子：让 AI 按我的底子现场生成教材。

具体说，我给它定了几条规矩：

  1. 所有新概念优先用 Java 类比讲——uv 就是 Maven，pydantic 就是 POJO + Bean Validation，装饰器就是注解 + AOP，asyncio 对标 CompletableFuture，Protocol 对标 interface。我已经会的东西一笔带过，别浪费我时间
  2. 每篇笔记只讲一个概念，写进我本地的 Obsidian，概念之间用双链连起来——一周下来自动长成一张知识图谱，图谱视图里能看见知识在长
  3. 每篇必须配动手任务，任务直接指向我代码仓库里的具体文件名，打开就能写

这套东西最大的好处是深度可调：我学到第二天说"我 Python 其实是零基础，之前说会基本语法是高估了"，它当天就把整个阶段的文档重构成"基础篇 9 篇（从变量不用声明类型讲起）+ 进阶篇 7 篇（Java 差异纠偏）"两轮，宁细勿跳。

网课做不到这件事。教材应该适配学生，而不是学生适配教材。

二、最重要的一条规矩：不准替我写代码

这条我要单独拎出来讲，因为它是整个方法的地基。

用 AI 学编程最大的陷阱，是它太好用了。你说"帮我实现一个装饰器"，三秒钟给你一个漂亮的、带类型注解的、比你写得好的版本。你看一眼："嗯，懂了。" 然后下一课继续。

两周后你会发现：Claude 学得很好，你什么都没学到。

所以我在项目记忆里写死了一条最高优先级约定，原文照抄：

教练模式：动手任务、项目、阶段测试的代码必须学员自己写。Claude 只能：讲解概念、review 学员写的代码、给方向性提示；学员明确表示卡住 15 分钟以上，才能给关键代码片段（仍不给完整实现）。禁止代写学习代码。

这条规矩带来的体验差异非常明显。举个真实的例子——

我写双模装饰器（既能 @log_call 又能 @log_call(level="DEBUG")）卡住了，去问它。它没给我代码，给的是这个：

def log_call(fn=None, *, level="INFO"):
    def decorator(func):
        ...          # 你已会的部分
    if fn is None:   # 说明是 @log_call(...) 用法
        return ???   # 该还回去一个"等着接函数的东西"——是谁？
    return ???       # 说明 fn 就是函数本人——直接给它做什么？

两个 ??? 是我自己填的。填完那一刻我真的懂了，而不是"看懂了"。

AI 天然会顺着你，所以你必须主动让它当把关人。 它每次 review 我的作业都会先跑 mypy，然后挑毛病——这一周我被抓出来的问题包括：注释和代码打架（3 次）、函数名拼写错误（3 次）、变量名遮蔽内置类型、"说完成了但其实只改了一半"（2 次）。这些毛病如果没人较真，会跟着我进项目、进生产。

三、六天里最扎心的几个坑（Java 老兵专属）

Java 的肌肉记忆在 Python 里会翻车，而且翻得很安静。挑几个最有代表性的：

1. == 和 is 的语义和 Java 正好是反的

a = [1, 2]
b = [1, 2]
a == b  # True  —— 比值，相当于 Java 的 equals
a is b  # False —— 比对象身份，相当于 Java 的 ==

顺带一个彩蛋：5 is 5 是 True，因为 CPython 缓存了 -5 到 256 的小整数——和 Java 的 Integer.valueOf 缓存 -128~127 是同一个设计，连"出了范围就翻脸"的坑都一样。但它属于实现细节，除了判 None 之外永远别用 is 比值。

2. 原地排序返回 None

s = s.sort()  # s 变成 None，灭顶之灾
s = sorted(s)  # 这才对

Python 的约定是：原地修改的方法返回 None，用返回值提醒你"我改的是你自己"。Java 的 Collections.sort() 惯性会让你在这栽一次。

3. 所有区间都含头不含尾——我用一个 FizzBuzz 证明了这有多阴

写 1 到 30 的 FizzBuzz，我写了 range(1, 30)。跑起来一切正常，输出看着挺对——但 30 恰好是 3 和 5 的公倍数，我把全场唯一压轴的那个 FizzBuzz 漏掉了，而且不报错。

4. 我的 setter 没生效，凶手是我自己

这个坑我卡了最久，值得完整贴出来：

class BankAccount:
    @property
    def balance(self): ...
    @balance.setter
    def balance(self, value):
        if value < 0:
            raise ValueError("不能为负")


BankAccount.balance = 100  # ← 凶手在这
a = BankAccount(200)
a.balance = -300  # 校验完全没触发，-300 畅通无阻

@property 的本质是挂在类上的描述符。我对类直接赋值 BankAccount.balance = 100，等于把整个 property（连带 setter）替换成了一个数字 100——校验代码从此人间蒸发。Java 里你没法在运行时把 getter/setter 抹掉换成公开字段，Python 允许，代价自负。

删掉那行之后还有第二层坑：getter 里写 return self.balance 会无限递归（读它自己触发它自己），存储字段必须错开叫 self._balance。

5. 子类构造器不会自动调父类，而且不报错

class Rect(Shape):
    def __init__(self):
        self.name = "Rectangle"  # 忘了 super().__init__()


r = Rect()  # 风平浪静，不报错
print(r.color)  # 半年后的某天：AttributeError

Java 编译器会自动插 super()，Python 什么都不插。炸点离病根十万八千里，这种 bug 比当场报错难查十倍。

6. 鸭子类型没有编译期保护——我亲手做了个实验

我写鸭子类型练习时，把方法名 render 拼成了 rander。两个类都错得整整齐齐，调用方也一样错，程序跑得好好的：

class JsonReport:
    def rander(self): ...  # 拼错了


class TextReport:
    def rander(self): ...  # 错得一致


def print_report(r):
    print(r.rander())  # 完美运行

Java 里 interface Renderable 会在编译期当场抓住这个拼写错误。Python 的隐式接口让它畅通无阻，直到某天有人按正确拼写写了个 render 方法的类传进来才炸。

而 Python 的解药是 Protocol + 类型检查。我下一课就用它验证了——故意让实现类和 Protocol 的签名不一致，mypy 立刻报出来：

error: Argument 1 to "broadcast" has incompatible type "ConsoleNotifier"; expected "Notifier"
note: Following member(s) of "ConsoleNotifier" have conflicts:
note:     Expected: def send(self, msg: str) -> str
note:     Got:      def send(self, msg: str) -> bool

"能抓住 rander 的那双眼睛"——从一个 bug 里长出学下一课的动机，这种学习顺序是网课给不了的。

7. async 里最贵的一课：让路 vs 堵路

这个我做了三组对照实验，数据自己说话。三个并发 HTTP 请求，其中一个加不同的"耗时 3 秒"：

组那个协程里放什么总耗时其他两个请求
A什么都不放0.95s基线
Bawait asyncio.sleep(3)3.20s照常完成（0.28s / 1.50s）
Ctime.sleep(3)（同步）4.36s被冻住，3 秒后才开工

B 和 C 总耗时看着差不多，差别全在其他任务的时间戳里：await asyncio.sleep 是把控制权交还事件循环（让路），time.sleep 是睡在马路中间（堵路），整个事件循环冻结。

4.36 ≈ 3（冻结）+ 1.36（真实工作），账目分毫不差。这就是"用了 async 框架却在 handler 里写同步阻塞调用"这类生产事故的原型。

顺带一个更隐蔽的坑：我第一次做这个实验时写的是 asyncio.sleep(3)——忘了 await。Python 只是创建了一个协程对象然后丢掉，sleep 根本没发生，只留下一行 RuntimeWarning: coroutine 'sleep' was never awaited。我当时没在意，基于那次的"数据"写了结论——结论当然是错的。

教训：看到 RuntimeWarning 不是"警告而已"，是"你的实验作废"的红色警报。

四、比语法更值钱的三个收获

说实话，第一周其实挺难熬的，上班要干活，下班了还要看代码，而且作为一个9年的JAVA，感觉整个人都是JAVA味的了，写py代码的时候，怎么写怎么难受，比如py的list居然啥都往里面塞，还不报错，作为一个JAVA,怎么看怎么难受

收获一：实验 > 结论

上面那张 async 对照表，如果我只是背下"async 适合 IO 密集"这句话，考试能过，工程上会翻车。是亲手跑出 0.95 / 3.20 / 4.36 三个数字并且能解释每一秒去哪了，这个知识才真正属于我。

现在我的习惯是：任何"应该是这样"的判断，先写五行代码验证一下。 这一周我靠这个习惯自己发现了教材里的一处逻辑错误（一道题说"两个班级的选课名单求交集"——班级互斥，交集恒为空，题目根本不成立），也发现了自己那次基于假数据的实验。

收获二："完成了"的定义

我说过好几次"完成了"，然后被 review 打回来——有时是改了没跑，有时是三个任务只做了两个。

最后立的规矩是："完成" = 改了 + 跑了 + 亲眼看到预期输出，三步缺一不可；说完成之前，把题目要求逐条对一遍。

这条规矩听起来像废话，但它是我这周被抓次数最多的问题。而它在工作中的代价，你我都懂。

收获三：错题本要有代码

我的错题本一开始是纯文本描述，复习起来毫无抓手。后来改成了卡片格式，每张卡包含：

  • ❌ 当时的写法（能复现问题的最小代码 + 一行症状注释）
  • ✅ 正确写法
  • 机制：为什么会这样（一句话）
  • 🔁 自测（折叠的问题 + 答案，先自己想再展开——天然的闪卡）
  • 关联笔记双链 + 复习打卡格 ⬜⬜⬜

现在有 31 张。复习时先看错误代码自己找茬，再展开自测题对答案，三格打满算彻底掌握。这批卡片是这一周最值钱的资产——它记录的不是"Python 知识"，而是"我这个人会在哪里犯错"。

五、两个和语法无关的坑，但更像真实工作

① 一条命令，把依赖搞坏了

我执行 uv add httpx pydantic 之后，之前跑通的异步脚本突然报错 ImportError: socksio。查了才明白：uv add 是声明式的——我原来声明的是 httpx[socks]（本机有 SOCKS 代理，必须这个 extra），重新 add 一个不带 extra 的同名包，等于把声明改掉了，socksio 被移除。

发现问题、定位原因、修复验证全流程走完，比做十道语法题有用。

② 脱敏改了代码就够了吗？不够

我早期练习里用了自己的真实姓名当示例数据。准备开源前我把工作区里的都改了，然后顺口问了一句"git 历史里还有吗"——

git show <旧提交>:phase0-python/basics/b01_variables.py
# 名字好好地躺在那里

Git 历史是不可变的快照链，改最新版不等于抹掉旧版；公开仓库 = 公开全部历史。 最后用 git filter-repo 重写了全部历史批量替换（提交轨迹和日期都保留，绿格子无损），再全历史搜索确认零残留。

这个坑在企业里泄露过无数 API key。我在第五天用自己的名字学到了它，成本是零。

六、我给自己设了一道门

这套方法里我觉得最值的一个设计：每个阶段结束必须考试，低于 80 分不许进下一阶段。

卷子是第一天就出好的——不是学完了照着我会的东西出题，这点很重要。笔试 8 道闭卷题，实操是写一个"并发网站体检工具"（pydantic 建模 + 异步并发 + 超时容错 + 装饰器计时 + 排序输出 + JSON 落盘）。

结果 92 分。但真正有价值的是扣分的那 8 分：

扣分一：我做得出来，但说不清楚。 笔试里问"GIL 存在的情况下为什么 async 还能提升吞吐"，我答"async 等待网络响应时会自动让出"——被扣 2 分。因为①没回答 GIL 那部分；②"自动"是错的，让出只发生在 await 这个显式让出点上，而反例正是我自己两天前做的实验（协程里塞 time.sleep 就一个字节码都不让）。

我做出了那三组数据，却在答题时把最关键的结论丢了。这在工程上无害，在面试里等于不会。

扣分二：mypy 说 Success，不代表没问题。 我的装饰器 def timed(fn): 一个类型注解都没写，而 mypy 默认不检查无注解函数的函数体——它内部一行都没被检查过，却给了我一个绿灯。这是同一个坑我第二次踩。

还有个彩蛋是运行时发现的：我的异常处理写着 except Exception as e: print(e)，实际输出是一行空白——httpx 的连接类异常 str(e) 经常是空字符串。"没崩"和"崩了能查"是两回事，得用 repr(e) 或 type(e).name。

一个我自己没料到的收获：AI 批卷比我预想的狠。它会跑 mypy、会实测（拿一个不存在的域名验证我的容错真的生效）、会逐条对着评分点扣分。这比"自我感觉良好"可靠太多了。
